🌲 Random Forest Algorithm

Core Algorithm

What is it? Random Forest is an ensemble learning method that builds multiple decision trees during training and outputs the average (regression) or majority vote (classification) of individual trees.

Why Random Forest?

  • Handles non-linear relationships — weather is not linear
  • Resistant to overfitting due to bagging (Bootstrap Aggregating)
  • Works well with mixed feature types (lat, lon, elevation, month)
  • No need for feature scaling (but we still scale for consistency)
  • Provides feature importance rankings automatically

Our Configuration

n_estimators = 150 → 150 decision trees in the forest
max_depth = 20 → Each tree can go 20 levels deep
min_samples_split = 5 → Need 5+ samples to split a node
min_samples_leaf = 2 → Leaves must have 2+ samples
n_jobs = -1 → Use all CPU cores for parallel training
random_state = 42 → Reproducible results

Why Not Other Algorithms?

AlgorithmProsWhy We Didn't Use It
Neural NetworkBest for complex patterns, image/textOverkill for tabular data with 12 features; needs more data & GPUs
Decision TreeSimple, interpretableSingle tree overfits easily; Random Forest = many trees averaged
Linear RegressionFast, simpleCan't capture non-linear weather patterns (monsoon seasonality etc.)
XGBoostOften better accuracyViable alternative; RF was chosen for simplicity + interpretability
SVMGood for small datasetsSlow on 50K samples; doesn't provide probability estimates easily

📊 Regression vs Classification

Problem Types

We use both types of supervised learning in this project:

🔢 Regression (Continuous Output)

Predicts a number — used for Temperature, Humidity, Wind Speed

RandomForestRegressor
Output: 38.9°C, 69.8%, 16.2 km/h
Loss: Mean Squared Error (MSE)
Metric: R² Score, MAE, RMSE

✅/❌ Classification (Binary Output)

Predicts a category — used for Rain / No Rain

RandomForestClassifier
Output: Rain (1) or No Rain (0)
Also gives: probability (e.g. 46.5%)
Metric: Accuracy, Precision, Recall, F1

⚙️ Feature Engineering

Data Preparation

Raw data isn't enough — we engineer new features to help the model learn patterns better.

Original Features (6)

  • latitude, longitude — Location on Earth
  • month — Which month (1-12)
  • day_of_year — Day number (1-365)
  • elevation — Height above sea level (meters)
  • distance_to_coast — How far from ocean (km)

Engineered Features (+6)

  • month_sin, month_cos — Cyclical encoding so Dec→Jan is smooth, not a jump from 12→1
  • day_sin, day_cos — Same for day of year
  • abs_latitude — Distance from equator (both hemispheres treated equally)
  • is_northern — Hemisphere flag (seasons are flipped N vs S)
💡 Why Cyclical Encoding? Without it, the model sees December (12) and January (1) as far apart. Using sin/cos, Dec and Jan become mathematically close — which reflects real weather continuity.
04

📏 StandardScaler (Normalization)

Preprocessing

What? Transforms each feature to have mean = 0 and standard deviation = 1.

Formula: X_scaled = (X - mean) / std_deviation

Example: Latitude ranges [-90, 90], Elevation ranges [0, 8000]
After scaling: both range approximately [-2, 2]
💡 Interview tip: Random Forest doesn't actually need scaling (it's tree-based, splits don't care about scale). But we apply it anyway because: (1) it's good practice, (2) it makes the model portable to other algorithms, (3) the scaler.joblib is saved and reused at inference time for consistency.
05

✂️ Train / Test Split

Validation

How We Split

train_test_split(X, test_size=0.2, random_state=42)

Total: 50,000 samples
Training: 40,000 (80%)
Testing: 10,000 (20%)

Why?

  • Model learns on 80% of data
  • We test accuracy on the 20% it has never seen
  • Prevents overfitting — if training R² is 0.99 but test R² is 0.50, the model memorized instead of learning
  • random_state=42 ensures same split every time for reproducibility
06

📈 Evaluation Metrics

Model Quality

Regression Metrics

  • R² Score — % of variance explained (1.0 = perfect). Our temp model: 0.91
  • MAE — Average error in original units. Temp MAE: ~2.1°C
  • RMSE — Like MAE but penalises big errors more. Temp RMSE: ~3.0°C

Classification Metrics

  • Accuracy — % correct predictions overall
  • Precision — Of predicted "Rain", how many were actually rain?
  • Recall — Of actual rain days, how many did we catch?
  • F1 Score — Harmonic mean of Precision & Recall

🌡️ Derived Meteorological Formulas

Post-Processing

Beyond ML predictions, we compute additional weather metrics using standard meteorological formulas:

Formulas Used

  • NWS Heat Index — Rothfusz regression for "feels like" in hot+humid conditions
  • Wind Chill — Environment Canada formula for cold+windy conditions
  • Magnus-Tetens Dew Point — Td = (b·α)/(a−α) where α = (a·T)/(b+T) + ln(RH/100)
  • UV Index — Based on solar declination angle + cloud/humidity attenuation
  • Visibility — Fog/haze/rain model with humidity thresholds
  • Pressure — Hypsometric equation with latitude, season, temperature

Global Validation Rules

  • Dew point must always be ≤ temperature
  • Hot + humid → feels like must be ≥ temperature
  • Cold + windy → feels like must be ≤ temperature
  • Humidity bounded 0-100%
  • Temperature bounded -89°C to 57°C (Earth records)
  • Every API response includes a validation object
